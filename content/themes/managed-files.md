---
title: Files the CMS manages
description: Which files in a site the CMS writes, why, and how to make one your own.

---

The admin, the plugin API and plugin pages need routes in the site's `app` directory. The CMS
writes these files itself, with `cms generate`, so updating the CMS can change them without your
help. `cms generate` runs before every `dev` and `build`.

## The files

| File                                                 | What it does                                                                                                  |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `src/cms/site.generated.ts`                          | Imports the plugins in `cms.config.json` (and the brand). The site's pages import it.                         |
| `src/cms/admin.generated.ts`                         | The same, with the plugins' [admin entries](/plugins/admin#the-admin-entry). The admin and the API import it. |
| `src/app/(cms)/layout.tsx`                           | The admin's root layout, separate from the site's.                                                            |
| `src/app/(cms)/admin/[[...segments]]/page.tsx`       | Every admin screen, core and plugin, from one route.                                                          |
| `src/app/(cms)/admin/forbidden.tsx`, `not-found.tsx` | The admin's 403 and 404 pages.                                                                                |
| `src/app/(cms)/api/p/[...path]/route.ts`             | Every plugin API route and admin action.                                                                      |
| `src/instrumentation.ts`                             | Records requests for plugins that trace them. A site with its own keeps it; see [Tracing](/hosting/tracing).  |
| `src/app/(site)/page.tsx`                            | The home page, until the site writes its own.                                                                 |
| `src/app/(site)/[...slug]/page.tsx`                  | Every plugin page on the site.                                                                                |

Each starts with this line:

```ts
// @generated by `cms generate`. Edits are overwritten; delete this line to keep yours.
```

The two `src/cms/*.generated.ts` modules are ignored by git, since they're rebuilt from
`cms.config.json` and the installed packages. The route files are committed, so the site's
history shows when an update changed them.

Keep the site's own files on `site.generated`. Next.js sends every client component a page imports
to its visitors, and `admin.generated` brings the plugins' admin screens.

## Making one your own

Delete the `@generated` line and the CMS never writes that file again: `cms generate` says
"kept" and moves on. Do this to change what a route does. You then keep it in step with the CMS
yourself: after updating, compare it with a new site's.

The home page is the exception. Writing your own is expected (see
[the home page](/themes/pages#the-home-page)), so `cms generate` doesn't warn about it.

## When a version stops managing a file

When an update replaces a managed file with others, `cms generate` removes the old one, as long as
it still carries the `@generated` line. One you made your own stays, and the files that would
clash with it aren't written.
